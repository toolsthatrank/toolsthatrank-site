Search Console URL Inspection API quota planner

The URL Inspection API lets a site make 2,000 inspection queries a day and 600 a minute, counted per property. Per project the cap is 10,000,000 a day and 15,000 a minute. Plan the budget, build the request and read the result.

Updated 2026-11-16

The per-site cap is 2,000 queries per day and 600 per minute. Google does not state on the limits page which HTTP status index.inspect returns when a quota is used up. This page lists the limits with their scopes, shows how the per-site and per-project quotas interact, and gives a planner for the number of URLs that one property can inspect per day.

The published limits

The numbers below are quoted from the vendor limits page, read 2026-11-16. Per property and per project are separate budgets, and both have to hold at once.

The limits page lists the index inspection quota as "2000 QPD" and "600 QPM" per site, and "10,000,000 QPD" and "15,000 QPM" per project. The 2022 blog post says the quota is enforced per Search Console website property, "2,000 queries per day" and "600 queries per minute". At 600 a minute, a script uses the 2,000 daily calls of one property in 3 minutes and 20 seconds (2,000 / 600 = 3.33 minutes). Spread evenly over 24 hours, 2,000 calls a day is about 1.4 calls a minute (2,000 / 1,440 minutes).

Build the POST body for an inspect call

The method urlInspection.index.inspect is a POST to https://searchconsole.googleapis.com/v1/urlInspection/index:inspect. Its body has inspectionUrl and siteUrl, plus an optional languageCode (default "en-US"). Google's reference says "Presently only the status of the version in the Google index is available; you cannot test the indexability of a live URL." A URL-prefix property must include a trailing / mark; a Domain property is written as sc-domain:example.com. The inspected URL must be under the property specified in siteUrl.

When a quota is used up

The limits page gives the quota numbers. It does not state the HTTP status or the error body that index.inspect returns when a quota is used up. Log the full error body of each failed call. Do not record a failed call as an inspected URL.

A script can handle this in three ways.

  • Stop the run when calls start to fail on quota.
  • Spread a large list over more days. A different project does not add calls to the per-site quota, because that quota counts calls querying the same site.
  • Keep a checkpoint of inspected URLs so a stopped run resumes and does not inspect the same URLs again.

Per site and per project interact

The two budgets hold at the same time. The 2022 blog post says that the quota is enforced per Search Console website property. The limits page adds the per-project numbers, 10,000,000 queries a day and 15,000 a minute, for calls made using the same Developer Console key. Each call counts toward the per-site quota of the property that it queries and toward the per-project quota of its key.

If several scripts use the same Developer Console key, the 15,000 a minute limit counts all of their calls together, and each property still has its own 600 a minute.

What one query returns

One query returns one UrlInspectionResult. It can hold index status, AMP, mobile usability and rich results. Google says that ampResult is absent if the page is not an AMP page, that richResultsResult is absent if no rich results are found, and that mobileUsabilityResult is deprecated. The quota counts queries. The dataState reference covers the Search Analytics API, which has a separate quota.

What this page cannot tell you

  • This page does not measure whether Google grants higher limits on request. The limits page does not describe a way to raise the URL inspection quota.
  • It does not replace the vendor reference. The quotes above are from the Google pages in the source list, read 2026-11-16.
  • It cannot raise your budget.
